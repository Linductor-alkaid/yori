# DEC-010：UDS IPC 端点、权限与管理员判定

> 状态：Accepted
> 日期：2026-09-09
> 负责人：Linductor-alkaid
> 冻结里程碑：M5
> 替代/被替代：无

## 背景与问题

总计划第 6 节将 IPC 端点列为 M5 冻结项（暂定 `/run/yori/yori.sock`、
`root:yori 0660`、`yori` 系统组）。M5 实现 UDS 传输与 `SO_PEERCRED` 鉴权前，
需要冻结四件事：端点路径与属主/权限、连接准入语义、管理员（admin）判定方式、
以及测试与部署对端点的可配置性。`SO_PEERCRED` 只携带连接时刻的主 GID，
而 Linux 文件权限检查同时覆盖主组与补充组，两种机制覆盖面不一致，管理员判定
必须显式定义。

## 决策

1. **端点与权限**：默认端点 `/run/yori/yori.sock`，属主 `root:yori`，模式
   `0660`（创建后立即 `fchmod`/`fchown` 收敛，不存在无权限窗口）。目录
   `/run/yori` 由 systemd `RuntimeDirectory=yori` 创建（M7 打包落地；M5 起
   daemon 在目录缺失时显式失败，不自行创建）。
2. **连接准入**：谁能连接由文件权限决定——`yori` 组成员（主组或补充组均可，
   内核文件检查天然覆盖两者）与非 root 其他用户被排除在连接之外。daemon 不
   在协议层重复做"是否允许连接"判定；`SO_PEERCRED` 取到的身份只用于 owner
   与 admin 授权（设计第 11.5/17 节）。
3. **管理员判定**：admin 指"可查看全部 Job 明细、取消任意 Job"的身份。判定
   在 daemon 侧基于 `SO_PEERCRED`：连接主 GID 等于任一配置的 admin GID，或
   连接 UID 属于 daemon 启动时从系统组数据库（`getgrgid` 成员表）解析出的
   admin 组成员 UID 集合。客户端声明的任何身份字段一律忽略。成员解析在
   daemon 启动时完成一次（组成员变更需重启 daemon 生效，属可接受的显式
   语义）；解析失败时该 GID 只保留主 GID 匹配。
4. **可配置性**：socket 路径、模式、属主与 admin GID 均为管理员 CLI/配置项
   （测试与非默认部署可覆盖），默认值即上述生产值。路径仅接受绝对路径且
   长度受 `sockaddr_un` 限制；daemon 拒绝把非 socket 文件当作陈旧端点删除。

## 备选方案

- 本机 TCP（127.0.0.1）：无可用的内核对端凭据机制，需自建令牌认证，扩大
  攻击面——拒绝。
- Linux abstract namespace socket：无文件系统权限模型，任何本地用户可连接
  ——拒绝。
- `/tmp` 下的 socket：sticky bit 下属主检查与竞态（改名替换）风险，且不符合
  FHS 运行时语义——拒绝。
- 管理员判定只看主 GID：强制管理员改动主组才能获得权限，运维代价高且和
  socket 组准入语义不一致——补充组解析一并纳入（决策第 3 条）。
- daemon 周期性重新解析组成员：引入与连接时刻的竞态且无明确收益——启动时
  解析一次足够。

## 影响与风险

- M5 起协议实现（帧边界、鉴权、脱敏、授权矩阵）以此为契约；M7 打包负责创建
  `yori` 组与 admin 组（建议名 `yori-admin`）并把用户加入对应组。
- 非 root 运行（测试）时 `fchown` 降级：配置属主非当前身份则启动显式失败，
  不静默忽略（测试注入当前用户属主 + 收紧的模式）。
- 组成员变更需重启 daemon：语义显式、写入本文档；如未来需要热更新，需新
  决策记录替代本条。
- `SO_PEERCRED` 的 PID 字段仅作诊断，不参与授权（客户端进程可 fork 后让子
  进程持有 socket；UID 才是稳定事实）。

## 验证方式

- 单测/集成测试（M5）：端点权限断言（模式、属主收敛）、非 socket 陈旧文件
  拒绝、owner/admin/第三方授权矩阵、客户端身份声明被忽略（协议中不存在身
  份字段，结构性保证 + 负向测试）。
- root 环境下的完整权限收敛与多用户连接准入断言在 M7 打包验收补跑（CI 无
  root 与多用户环境，按工程规范第 4 节记录补跑条件）。
